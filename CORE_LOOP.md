# AATE — Core Loop и правила матча

## 1. Роли и термины
- `Активный игрок` — тянет текущий вопрос и выбирает свой реальный ответ.
- `Угадывающий игрок` — пытается предсказать ответ активного игрока.
- `Host Screen` — общий экран матча (вопрос, фаза, счет, подсказка о ходе).
- `Player Phone` — личный экран игрока (ввод, таймер, подтверждение выбора).

## 2. Подготовка матча
1. На `Host Screen` создается комната.
2. Два игрока заходят с телефонов в комнату, вводят ники.
3. Хост выбирает размер колоды: `10`, `20` или `40` вопросов.
4. Сервер фиксирует порядок раундов и стартового активного игрока.

## 3. Структура одного раунда

### Фаза A: Показ вопроса
- На `Host Screen` показываются текст вопроса и 3 варианта ответа.
- На телефонах можно дублировать вопрос и варианты для удобства.
- Интерфейс явно показывает роли: кто сейчас активный, кто угадывает.

### Фаза B: Скрытый выбор активного игрока
- Активный игрок на своем телефоне выбирает вариант `1/2/3`.
- Его выбор не виден второму игроку до раскрытия.
- После подтверждения игрок видит состояние ожидания.

### Фаза C: Прогноз угадывающего игрока
- Угадывающий на своем телефоне выбирает вариант, который, как он думает, выбрал активный игрок.
- После подтверждения также переходит в ожидание.

### Фаза D: Раскрытие
- Когда оба выбора получены (или истекли таймеры по правилам), сервер раскрывает:
  - реальный ответ активного игрока;
  - прогноз угадывающего.
- На `Host Screen` отображается результат раунда.

### Фаза E: Начисление очков
- Если прогноз совпал с реальным ответом, угадывающий получает `+1` очко.
- Если не совпал — `0` очков.
- Очки начисляются только внутри текущего матча.

### Фаза F: Переход к следующему раунду
- Роли меняются местами.
- Счет сохраняется.
- Переход к следующему вопросу.

## 4. Таймер и поведение при просрочке
- У каждой интерактивной фазы (выбор/прогноз) есть таймер.
- Источник истины по времени — сервер.
- Для MVP рекомендуем правило:
  - если игрок не успел, его выбор считается пропущенным;
  - при пропуске угадывающего очко не начисляется;
  - при пропуске активного игрока раунд помечается как технически пустой и игра идет дальше.

Это правило сохраняет темп матча и упрощает первую реализацию.

## 5. Конец матча
- Матч завершается, когда сыграны все вопросы выбранной колоды (10/20/40).
- Победитель — игрок с большим количеством очков.
- При равенстве — ничья.

## 6. Экранные обязанности

### Host Screen
- Отображает:
  - ники игроков;
  - текущую фазу раунда;
  - чей ход и кто угадывает;
  - вопрос и варианты;
  - счет и прогресс по колоде (`например, 7/20`).

### Player Phone
- Экран входа:
  - ввод/редактирование ника;
  - ввод кода комнаты и подключение.
- Экран матча:
  - таймер;
  - текущая роль;
  - вопрос + 3 варианта;
  - кнопки выбора `1/2/3`;
  - состояния "ответ отправлен" / "ожидание раскрытия".

## 7. Правила качества контента (вопросов)
Чтобы механика угадывания работала стабильно, вопросы должны:
- быть понятными за одно чтение;
- содержать ровно 3 различимых варианта;
- не иметь очевидно "правильного" варианта;
- вызывать выбор между близкими по привлекательности опциями;
- не зависеть от узкоспециального контекста.

## 8. Баланс и темп MVP
- Рекомендуемая длительность раунда: 20-35 секунд.
- Режим 10 вопросов — быстрый матч (первая сессия).
- Режим 20 вопросов — основной режим.
- Режим 40 вопросов — длинная сессия для вовлеченных игроков.
